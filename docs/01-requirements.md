# 01. Требования

Источник: «Лабораторный практикум по курсу Web-технологии» (методичка преподавателя, лежит в `docs/source/`). Методичка написана в 2009 году под PHP, MySQL и Apache. Преподаватель разрешил Node.js, поэтому все требования выполняются на стеке из [03-architecture.md](03-architecture.md), а не на PHP.

Тема проекта — вариант №2 из приложения 1: **«Заказ билетов (вид транспорта – билет – заказчик – номер рейса)»**. Сайт только про авиаперелёты, поэтому «вид транспорта» реализован как **модель воздушного судна** (Airbus A320neo, Boeing 737-800 и т.д.) — см. [04-data-model.md](04-data-model.md).

Каждое требование ниже имеет код (например, `L1-07`). Коды используются в задачах, PR и при сдаче, чтобы было видно, что чем закрыто.

## Лаба 2. Представление структурированных данных

Срок по методичке: второй месяц.

В методичке лаба называется «XML и XSL». Данные лежат в двух видах: JSON для «Пресс-центра» и тот же набор в **XML** со схемой XSD и преобразованием XSL для вкладки «XML» — [ADR-0010](adr/0010-lab-tabs-and-xml.md).

| Код | Требование методички | Чем закрываем |
|---|---|---|
| L2-01 | Структурировать новости тегами: 15–20 записей, 5–7 тегов | Файл `content/press/press-releases.xml`: 18 пресс-релизов, у каждого 7 полей — атрибут `id` и теги `title`, `date`, `category`, `author`, `summary`, `body`. Те же данные — в `press-releases.json` |
| L2-02 | Описать структуру данных | Схема XSD `content/press/press-releases.xsd` (проверка `xmllint` в тестах), JSON Schema и Zod-схема — данные проверяются при загрузке |
| L2-03 | Преобразование данных в HTML (XSL) | `content/press/press-releases.xsl`: XSL-преобразование в HTML на сервере, `/xml/transform`. Таблица вкладки — серверная функция и React-компоненты |
| L2-04 | Сортировка и выборка | Вкладка «XML»: поиск набора символов во всех колонках, выборка по категории и автору, сортировка по любой колонке в обе стороны, выбор колонок; то же умеет XSL. Параметры — в адресе страницы |
| L2-05 | Приложение для представления данных, включённое в сайт | Вкладка «XML» (`/xml`) в основном меню; JSON-вариант — «Пресс-центр» (`/press`) |
| L2-06 | Демонстрация | На вкладке «XML» — «Открыть XML», «Скачать XML», «Преобразование XSL», «Файл XSL», «Схема XSD»; на `/press` — исходный JSON и схема |

## Лаба 3. Web-приложение с базой данных

Срок по методичке: третий месяц.

| Код | Требование методички | Чем закрываем |
|---|---|---|
| L3-01 | Приложение, работающее с базой данных | Весь сайт на PostgreSQL; для отчёта — вкладка «БД» (`/database`) в основном меню: паспорт базы и запросы к ней. Подробные отчёты о продажах — «Аналитика» (`/analytics`) |
| L3-02 | 3–5 типов запросов | Пять видов запросов на вкладке «БД» с формами и текстом выполненного SQL, плюс пять отчётов «Аналитики», см. ниже |
| L3-03 | Графики и диаграммы | Линейный график, столбчатые и круговая диаграммы |
| L3-04 | Агрегированные данные | `COUNT`, `SUM`, `AVG`, `MAX`, группировки по периоду, авиакомпании, направлению |

Запросы вкладки «БД» (`/database`):

1. **Поиск рейсов** — условия по городам, авиакомпании и датам, сортировка, по 20 на страницу.
2. **Авиакомпания и направление** — связанные списки (только сочетания с рейсами); маршруты с MIN, AVG, MAX цены и числом проданных мест.
3. **Сводка по авиакомпаниям** за период — COUNT, SUM, AVG, MAX; столбчатая диаграмма и таблица точных значений.
4. **Динамика продаж** по месяцам — линейный график и таблица.
5. **Оценки сайта** — распределение и средняя, минимальная, максимальная оценки; столбчатая диаграмма.

Над запросами — паспорт базы: объём, число таблиц и записей, состав, полнота, актуальность, автор и ссылка на ввод данных в админке.

Отчёты страницы `/analytics`:

1. **Выручка по месяцам** за выбранный период — линейный график.
2. **Топ-10 направлений** по числу проданных билетов — столбчатая диаграмма.
3. **Заполняемость рейсов** по авиакомпаниям и моделям самолётов — доля мест улетевших рейсов, проданных через Avocado Travel (демо-данные продают лишь малую часть мест, см. [04-data-model.md](04-data-model.md#демо-данные)), — столбчатая диаграмма.
4. **Структура продаж**: доля классов «эконом» и «бизнес», доля отмен — круговые диаграммы.
5. **Отчёт с фильтрами**: период, авиакомпания, направление → таблица с итогами (количество, сумма, средний чек, максимальный чек).

Плюс статистика рекламы (показы, клики, CTR) из сервиса L1-S12.

## Лаба 4. Обмен данными между приложениями

Срок по методичке: четвёртый месяц.

| Код | Требование методички | Чем закрываем |
|---|---|---|
| L4-01 | Обмен данными между приложениями | Публичный REST API `/api/v1` в формате JSON с документацией OpenAPI на странице `/api/docs` |
| L4-02 | Лента новостей для подписки (в методичке RSS) | RSS 2.0 по адресу `/feed.xml` и JSON Feed 1.1 по адресу `/feed.json`, генерируются из базы новостей |
| L4-03 | Выгрузка в табличный формат (CSV) | Выгрузка рейсов, новостей и отчётов аналитики в CSV; общая лента вкладки «RSS» — в CSV и в тексте ASCII через табуляцию со списком полей в первой строке |
| L4-04 | Выгрузка в XML и «ASCII в XML-тегах» | Общая лента вкладки «RSS» (`/rss/export`) — в XML, RSS и «ASCII в XML-тегах» (тот же текст ASCII внутри `<payload>`, список полей и правила разбора — в `<fields>`), ADR-0010 |
| L4-05 | Получение данных из внешних источников | Импорт новостей авиаотрасли из внешних RSS-лент по расписанию; ленты подключает и отключает администратор на вкладке «RSS». Любой посетитель может загрузить свой RSS-файл — сайт разберёт его на записи |
| L4-06 | Загрузка в другую СУБД или прикладная обработка | Обработка импортированных новостей: удаление дублей, автоматические теги, сохранение в базу, показ в «Новостях отрасли» и в общей ленте вкладки «RSS» |

Подробности — [05-api.md](05-api.md).

## Требования к оформлению отчётов

Отчёт по каждой лабе оформляется по шаблонам из приложений методички. Отчёты не входят в репозиторий кода и готовятся отдельно.
