# ADR-0013. Значения выпадающих списков хранятся в справочнике, поиск — и по справочникам

**Статус:** принято.

## Контекст

Замечания преподавателя по лабе 3 (ноябрь 2026):

1. При вводе большинство атрибутов городов и авиакомпаний заполняется из выпадающих списков, которые строятся выборкой единичных значений из базы.
2. Если нужного значения нет, рядом со списком — кнопка «Добавить», она открывает форму нового значения. Новое значение появляется в списках для ввода и для поиска.
3. Все списки сортируются.
4. Поиск по двум связанным значениям всегда даёт результат. «Выбрал Москва — компания Новая — нет результатов».

В формах города и авиакомпании списком был только часовой пояс, и то не из базы. У авиакомпании не было ни одного повторяющегося атрибута: название, код и описание у каждой свои. Фильтр `/admin/flights` («Город», «Авиакомпания») не был связанным, из-за этого и получалось сочетание без результата.

Замечания 2 и 4 спорят: новый город без рейсов должен сразу появиться в списках поиска, но поиск по рейсам для него ничего не найдёт.

## Решение

- **Таблица `reference_values`** (вид, значение; пара уникальна): страны, части света, часовые пояса, типы авиакомпаний. Списки форм строятся `SELECT DISTINCT` по ней и сортируются сервисом по русскому алфавиту.
- **Новые поля:** у города — часть света, у авиакомпании — страна, тип и базовый город. Страны у городов и авиакомпаний — один список.
- **Кнопка «+ Добавить»** у каждого такого списка открывает окно на этой же странице: введённое в форме не теряется. Значение сохраняется сразу и уже выбрано в списке. У базового города в окне открывается вся форма города.
- **Дубли.** То же значение другими буквами («россия») не создаёт новую строку — выбирается имеющееся. Часовой пояс должен существовать на самом деле: его проверяет `Intl`.
- **Проверка на сервере.** Сервис принимает только значения из справочника, запрос в обход формы не пройдёт. Город, который у авиакомпании базовый, удалить нельзя.
- **Поиск по справочникам.** В «Поиске по двум атрибутам» к «Авиакомпании и направлению» добавлены «Страна и город», «Часть света и часовой пояс», «Страна и авиакомпания», «Тип и авиакомпания». Их списки строятся из самих городов и авиакомпаний, поэтому новые значения видны сразу и без рейсов, и результат есть всегда. Поиск по рейсам остаётся как был: в его списках только сочетания с рейсами.
- **Сочетание без записей не даёт пустой результат.** Общая функция `repairSelection` (`src/shared/lib/linked.ts`) снимает условие, которое с уже принятыми не даёт записей; страница сообщает об этом. Это закрывает старые ссылки и выбор, сделанный до загрузки скрипта. Применяется на вкладке «БД», в `/admin/flights` и в «Аналитике».
- Фильтр `/admin/flights` теперь связанный: общий компонент `LinkedSelects`.

## Альтернативы

- **Только `SELECT DISTINCT` по колонкам городов и авиакомпаний, без своей таблицы.** Новая страна существовала бы лишь в браузере до сохранения города: брошенная форма теряла бы значение, а в другой форме его бы не было. Части света и типы без единого использования в списках не появились бы.
- **Отдельная таблица на каждый список.** Четыре одинаковые таблицы с одной колонкой — без пользы.
- **«Добавить» как переход на отдельную страницу**, как в форме рейсов. Введённое в форме терялось бы при каждом нажатии.
- **Поиск только по рейсам и объяснение в письме.** Преподаватель проверяет дословно, замечание 2 осталось бы невыполненным.

## Последствия

- Миграция `0015` создаёт таблицу и заполняет новые поля: у городов и авиакомпаний демо-данных — заданные значения, у заведённых на сайте часть света — по часовому поясу аэропорта, базовый город — откуда больше всего рейсов, страна — «Россия», тип — «Классическая». На боевых базах она применяется сама при запуске.
- Удалять значения из списков нельзя: случайно добавленное остаётся в списке. Этого пока не просили.
- Кнопка «+ Добавить» работает только с JavaScript: для формы администратора это допустимо.
