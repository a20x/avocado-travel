# ADR-0004. JSON вместо XML во второй и четвёртой лабах

**Статус:** принято, с риском

## Контекст

Методичка 2009 года требует во второй лабе XML и XSL, в четвёртой — RSS (XML) и выгрузку в XML. Сегодня в веб-разработке для обмена данными используется JSON, а для отображения — компоненты (React). Автор проекта хочет работать с современными форматами.

## Решение

- Лаба 2: данные в JSON (`content/press/press-releases.json`), структура описана JSON Schema и Zod, преобразование в HTML — серверная функция и React-компоненты.
- Лаба 4: публичный REST API на JSON, лента в формате JSON Feed, выгрузки в CSV и JSON. Внешние ленты читаются в их формате (RSS/Atom), потому что выбирать его мы не можем.

## Риск

Лаба 2 в методичке называется «XML и XSL», и преподаватель может не принять JSON. Тогда:

- для лабы 2 добавляется XML-файл с теми же данными, XSD-схема и XSLT-шаблон, преобразование выполняется **на сервере** (Chrome удаляет XSLT из браузера с ноября 2026 года);
- для лабы 4 добавляются `/rss.xml` и формат `xml` у выгрузок.

## Как архитектура это учитывает

Данные и их представление разделены: модуль `press` сначала загружает данные в типизированную модель, а форматы вывода (HTML, JSON, при необходимости XML) — отдельные функции над этой моделью. То же для выгрузок в модуле `exchange`. Добавление XML — новый формат, а не переписывание модуля.
