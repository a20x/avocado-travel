# ADR-0001. Модульный монолит на Next.js

**Статус:** принято

## Контекст

Нужен сайт с серверной частью: база данных, авторизация, модерация по IP, публичный API. По требованиям лабы 1 сайт регистрируется в поисковике и проходит валидацию W3C, поэтому страницы должны приходить в браузер готовым HTML. Стек — максимально востребованный на рынке: TypeScript, React, Node.js.

## Решение

Одно приложение на Next.js (App Router), где фронтенд и сервер пишутся вместе. Внутри — модули по сервисам и слои внутри модулей ([03-architecture.md](../03-architecture.md)).

## Альтернативы

- **React SPA + отдельный бэкенд на NestJS.** Тоже востребовано, но два приложения, два деплоя, вдвое больше настройки. Страницы SPA приходят пустыми и дорисовываются JavaScript — хуже для поисковиков и валидатора.
- **Статический сайт + сторонние сервисы** (как в первой версии проекта). Не позволяет банить по IP, хранить данные общими для всех посетителей и делать лабу 3.

## Последствия

- Один деплой, одна кодовая база, общие типы для клиента и сервера.
- Слои модулей устроены так же, как в NestJS (маршрут → сервис → репозиторий), поэтому при необходимости серверная часть выносится в отдельный сервис без переписывания логики.
- Нужен хостинг с поддержкой Node.js, GitHub Pages больше не подходит.
