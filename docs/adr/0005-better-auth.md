# ADR-0005. Авторизация через Better Auth

**Статус:** принято

## Контекст

Нужны регистрация и вход покупателей по почте и паролю, роль администратора, защита разделов. Писать авторизацию с нуля — частый источник уязвимостей.

## Решение

Библиотека Better Auth: регистрация, вход, хэширование паролей, сессии в cookie, данные в нашей PostgreSQL через адаптер Drizzle. Роль хранится полем `role` у пользователя.

## Альтернативы

- **Auth.js (NextAuth)** — популярна, но вход по паролю в ней сделан по остаточному принципу.
- **Своя реализация** — полезна для обучения, но рискованна; не стоит делать в первом проекте.
- **Внешние сервисы (Clerk и подобные)** — данные пользователей у третьей стороны, возможны проблемы с доступностью и оплатой из России.

## Последствия

- Подтверждение почты не используется (решение автора), поэтому почтовый сервис не нужен.
- Вход через Яндекс или VK можно добавить позже конфигурацией.
