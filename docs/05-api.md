# 05. Публичный API и обмен данными

Этот документ закрывает лабу 4 ([01-requirements.md](01-requirements.md#лаба-4-обмен-данными-между-приложениями)).

## Принципы

- Базовый адрес: `/api/v1`. Номер версии в адресе позволяет менять API, не ломая тех, кто уже им пользуется.
- Формат по умолчанию — JSON (`application/json; charset=utf-8`).
- Публичные адреса только читают данные и доступны без авторизации. Персональные данные (заказы, пользователи) через публичный API не отдаются.
- Описание всех адресов — спецификация OpenAPI 3.1 по адресу `/api/v1/openapi.json`, генерируется из тех же Zod-схем, которыми API проверяет параметры (`z.toJSONSchema`, без сторонних библиотек). Интерактивная документация — страница `/api/docs`: адреса, параметры и форма «Попробовать» у каждого, собранные из этой же спецификации.
- Деньги — целые копейки (`520000` = 5 200 ₽), валюта — `RUB`. Время — ISO 8601 в UTC.
- Ответы разрешено читать с любых сайтов (`Access-Control-Allow-Origin: *`): API для того и сделан, чтобы данными пользовались другие приложения.
- API-маршруты тонкие: проверяют параметры и вызывают сервисы модулей, как и Server Actions.

## Формат ответов

Список (у справочников `meta` содержит только `total`):

```json
{
  "data": [{ "id": "…", "number": "LST 1204" }],
  "meta": { "page": 1, "pageSize": 20, "total": 134 }
}
```

Один объект:

```json
{ "data": { "slug": "avocado-travel-otkrylsya", "title": "…" } }
```

Ошибка:

```json
{
  "error": { "code": "VALIDATION_ERROR", "message": "Параметр date должен быть в формате YYYY-MM-DD" }
}
```

Коды ответа: `200` — успех, `400` — неверные параметры (`VALIDATION_ERROR`, а для поиска рейсов ещё `SAME_CITY`, `UNKNOWN_PLACE`, `DATE_OUT_OF_RANGE`), `404` — не найдено (`NOT_FOUND`), `429` — слишком много запросов (`RATE_LIMITED`, с заголовком `Retry-After`), `500` — ошибка сервера (`INTERNAL_ERROR`). Неверный параметр — всегда `400` с понятным сообщением, а не молчаливая подмена значения по умолчанию.

Неизвестный адрес под `/api/v1` тоже отвечает ошибкой в этом формате (`404`, `NOT_FOUND`), а не HTML-страницей.

Пагинация: параметры `page` (с 1) и `pageSize` (по умолчанию 20, максимум 100).

## Адреса

| Метод и адрес | Что отдаёт | Параметры |
|---|---|---|
| `GET /api/v1/airports` | Аэропорты | — |
| `GET /api/v1/airlines` | Авиакомпании | — |
| `GET /api/v1/aircraft-models` | Модели самолётов со схемой салона | — |
| `GET /api/v1/flights` | Поиск рейсов в одну сторону на дату | `from`, `to` — IATA-код аэропорта (`SVO`) или код города (`moscow`), `date`, `passengers`, `class`, `sort`, `page`, `pageSize` |
| `GET /api/v1/flights/{id}` | Рейс с ценами, свободными местами и схемой салона с занятостью | — |
| `GET /api/v1/news` | Новости | `source` (`site` / `external`), `category`, `page`, `pageSize` |
| `GET /api/v1/news/{slug}` | Одна новость | — |
| `GET /api/v1/stats/summary` | Сводная статистика посещений: сегодня, за период, всего, по дням и разделам | `from`, `to` |
| `GET /api/v1/analytics/{report}` | Данные отчёта аналитики: `revenue`, `destinations`, `occupancy`, `structure`, `routes` | `from`, `to`, `airline` (код), `destination` (код города) — как на странице `/analytics` |

## Выгрузки

Каждая выгрузка доступна в двух форматах — параметр `format` (по умолчанию `csv`). Выгрузки описаны в OpenAPI вместе с остальными адресами (раздел «Выгрузки» на `/api/docs`), а ошибки параметров у них — в обычном формате API:

| Адрес | Что выгружается |
|---|---|
| `GET /api/v1/export/flights?format=csv\|json&date=…` | Расписание: все рейсы с вылетом в этот день по Москве; необязательные `from`, `to` (IATA или код города) сужают до маршрута. Время — местное, в JSON ещё и UTC |
| `GET /api/v1/export/news?format=csv\|json` | Опубликованные новости без полного текста (он есть в API и ленте); необязательный `source` |
| `GET /api/v1/export/analytics/{report}?format=csv\|json&from=…&to=…` | Отчёт аналитики с теми же фильтрами, что на странице (`airline`, `destination`) |

CSV-формат:

- кодировка UTF-8 с BOM, чтобы Excel правильно показывал кириллицу;
- разделитель — точка с запятой (так Excel в русской локали открывает файл сразу по столбцам);
- первая строка — названия полей;
- значения с разделителем, кавычками или переносами строк заключаются в двойные кавычки;
- заголовок `Content-Disposition: attachment; filename="flights-2026-11-14.csv"`;
- деньги — в рублях, дроби — с запятой (так их понимает Excel в русской локали); в JSON-выгрузке — те же столбцы с латинскими ключами, деньги в копейках, как во всём API;
- текст, начинающийся с `=`, `+`, `-` или `@`, получает апостроф впереди: иначе Excel выполнил бы его как формулу (CSV injection) — важно для новостей из чужих лент.

Кнопки «Скачать CSV» — у каждого отчёта на странице аналитики (с текущими фильтрами), на странице результатов поиска (расписание маршрута на дату) и на `/api/docs` (раздел «Выгрузки и лента»).

## Лента новостей

`GET /feed.json` — лента новостей сайта в формате [JSON Feed 1.1](https://www.jsonfeed.org/version/1.1/), это JSON-аналог RSS: 20 последних опубликованных новостей сайта (запланированные не попадают), с полным текстом, рубрикой и тегами, адреса абсолютные. Тип ответа — `application/feed+json`, кэш — 10 минут. В `<head>` всех страниц есть ссылка `<link rel="alternate" type="application/feed+json">`, чтобы программы-читалки находили ленту автоматически.

## Импорт внешних лент

- Список лент — `src/modules/exchange/feeds.ts`: код, название, адрес, рубрика (`aviation` — «Авиация», `travel` — «Туризм»). Сейчас это Aviation21, Турдом и «Путешествия» Ленты.ру — все проверены на доступность из России. Формат выбирают внешние сайты, поэтому читаем XML: RSS 2.0, RSS 1.0 (RDF) и Atom (библиотека `fast-xml-parser`). Кодировка — из `Content-Type` или объявления XML, windows-1251 тоже понимается.
- Задание по расписанию раз в 6 часов — `GET/POST /api/cron/import-feeds` с `Authorization: Bearer <CRON_SECRET>` (как автоотмена заказов); вручную — `pnpm job:import-feeds`. Отвечает отчётом по каждой ленте: сколько получено, добавлено и почему пропущено.
- Обработка (L4-06):
  - ссылка без меток (`utm_*`, `from`, `ref`) и якоря — по ней убираются дубли: в одном импорте и между лентами — в памяти, с уже сохранёнными — уникальным индексом `external_url` в базе;
  - заголовок и описание — обычный текст: теги HTML удалены, сущности (`&nbsp;`, `&laquo;`, `&#160;`) раскрыты; описание — до 300 знаков по границе слова;
  - **полный текст не храним**: только заголовок, краткое описание и ссылку на оригинал — статья принадлежит источнику;
  - автоматические теги по словарю ключевых слов: аэропорты, расписание, багаж, визы, цены, туризм, курорты, безопасность, самолёты;
  - **новости о настоящих авиакомпаниях не импортируются**: в проекте авиакомпании выдуманные (решение автора). Отсев — по словарю названий («Аэрофлот», Turkish Airlines…) и приметам: «авиакомпания «…»» или латиницей, «… Airlines/Airways», «Air …», номер рейса с кодом авиакомпании («рейс SU 1234»);
  - из ленты берутся 30 последних записей; записи старше 30 дней не импортируются, а уже сохранённые старше 30 дней удаляются при каждом импорте — база на бесплатном хостинге не разрастается; дата из будущего считается «сейчас».
- Защита: лента больше 5 МБ и документ с `DOCTYPE` не разбираются (атака «billion laughs» через объявления сущностей), на ответ ленты — не больше 15 секунд.
- Если лента недоступна или сломана, задание пишет предупреждение в лог и продолжает с остальными.

## Ограничения

- Публичные адреса ограничены по частоте: не более 60 запросов в минуту с одного IP, иначе `429`.
- Ответы справочников кэшируются на 10 минут.
