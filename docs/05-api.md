# 05. Публичный API и обмен данными

Этот документ закрывает лабу 4 ([01-requirements.md](01-requirements.md#лаба-4-обмен-данными-между-приложениями)).

## Принципы

- Базовый адрес: `/api/v1`. Номер версии в адресе позволяет менять API, не ломая тех, кто уже им пользуется.
- Формат по умолчанию — JSON (`application/json; charset=utf-8`).
- Публичные адреса только читают данные и доступны без авторизации. Персональные данные (заказы, пользователи) через публичный API не отдаются.
- Описание всех адресов — спецификация OpenAPI 3.1 по адресу `/api/v1/openapi.json`, генерируется из Zod-схем. Интерактивная документация — страница `/api/docs`.
- API-маршруты тонкие: проверяют параметры и вызывают сервисы модулей, как и Server Actions.

## Формат ответов

Список:

```json
{
  "data": [{ "id": "…", "number": "LST 1204" }],
  "meta": { "page": 1, "pageSize": 20, "total": 134 }
}
```

Ошибка:

```json
{
  "error": { "code": "VALIDATION_ERROR", "message": "Параметр date должен быть в формате YYYY-MM-DD" }
}
```

Коды ответа: `200` — успех, `400` — неверные параметры, `404` — не найдено, `429` — слишком много запросов, `500` — ошибка сервера.

Пагинация: параметры `page` (с 1) и `pageSize` (по умолчанию 20, максимум 100).

## Адреса

| Метод и адрес | Что отдаёт | Параметры |
|---|---|---|
| `GET /api/v1/airports` | Аэропорты | — |
| `GET /api/v1/airlines` | Авиакомпании | — |
| `GET /api/v1/aircraft-models` | Модели самолётов со схемой салона | — |
| `GET /api/v1/flights` | Поиск рейсов | `from`, `to` (IATA), `date`, `passengers`, `class`, `sort`, `page`, `pageSize` |
| `GET /api/v1/flights/{id}` | Рейс с занятостью мест | — |
| `GET /api/v1/news` | Новости | `source` (`site` / `external`), `category`, `page`, `pageSize` |
| `GET /api/v1/news/{slug}` | Одна новость | — |
| `GET /api/v1/stats/summary` | Сводная статистика посещений | `from`, `to` |
| `GET /api/v1/analytics/{report}` | Данные отчётов аналитики | `from`, `to`, `airline`, `route` |

## Выгрузки

Каждая выгрузка доступна в двух форматах — параметр `format`:

| Адрес | Что выгружается |
|---|---|
| `GET /api/v1/export/flights?format=csv\|json&date=…` | Расписание рейсов на дату |
| `GET /api/v1/export/news?format=csv\|json` | Новости |
| `GET /api/v1/export/analytics/{report}?format=csv\|json&from=…&to=…` | Отчёт аналитики |

CSV-формат:

- кодировка UTF-8 с BOM, чтобы Excel правильно показывал кириллицу;
- разделитель — точка с запятой (так Excel в русской локали открывает файл сразу по столбцам);
- первая строка — названия полей;
- значения с разделителем, кавычками или переносами строк заключаются в двойные кавычки;
- заголовок `Content-Disposition: attachment; filename="flights-2026-11-14.csv"`.

Кнопки «Скачать CSV» есть на страницах аналитики, расписания и на `/api/docs`.

## Лента новостей

`GET /feed.json` — лента новостей сайта в формате [JSON Feed 1.1](https://www.jsonfeed.org/version/1.1/), это JSON-аналог RSS. В `<head>` всех страниц есть ссылка `<link rel="alternate" type="application/feed+json">`, чтобы программы-читалки находили ленту автоматически.

## Импорт внешних лент

- Список лент — в конфиге модуля `exchange`: адрес, название, категория. Это RSS- и Atom-ленты новостей авиации и путешествий; их формат выбирают внешние сайты, поэтому читаем XML.
- Задание по расписанию раз в 6 часов скачивает ленты, разбирает их и сохраняет новые записи в таблицу `news` с `source = external`.
- Обработка (L4-06): удаление дублей по ссылке, очистка HTML, автоматические теги по словарю ключевых слов (например, «аэропорт», «авиакомпания», «багаж»), сохранение источника.
- Если лента недоступна или сломана, задание пишет предупреждение в лог и продолжает с остальными.

## Ограничения

- Публичные адреса ограничены по частоте: не более 60 запросов в минуту с одного IP, иначе `429`.
- Ответы справочников кэшируются на 10 минут.
